# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Fixed
- Search bar needing two taps to bring up the keyboard: the glass capsule's own interactive touch-tracking was winning the first tap for its press animation, so `TextField` only became first responder on a second tap. A `simultaneousGesture` now sets focus directly on the first tap.
- Google API cost exposure: `PlaceDetailViewModel.load(for:)` fired a fresh Text Search + full Place Details call (Contact + Atmosphere fields, the priciest tier) on every single place-card open, including reopening the exact same favorite/recent/search result. Added an in-memory `PlaceDetailsCache` (1-hour TTL, keyed by name+coordinate and by Google's place ID) shared across `GooglePlacesService` instances, so repeat views of an already-seen place cost zero additional calls within the hour. Also fixed `DirectionsViewModel.scheduleCalculation()`: cancelling the in-flight `Task` when a mode/avoid-preference changes only took effect after the network response came back, so rapid toggling (e.g. flipping two "Avoid" switches back to back) still billed one Routes API call per toggle. Added a 350ms debounce with a cancellation check before the request goes out, so rapid changes collapse into one call.

### Fixed
- Favorites were unreachable: the only "Add to Favorites" control (a circle in the search-results list) only rendered when the results list was showing an empty query *and* a place was already selected — a state combination the app's own navigation never produced, since selecting a place always cleared the query-empty condition and left the results list. Added a real favorite-star toggle to the place detail card itself (`favoriteButton`, next to share/close), the reachable, expected location.

### Added
- Editable Favorites: rename a saved place and give it a custom emoji/color pin instead of the auto-derived category icon, via an edit sheet opened from a swipe action in the full Favorites list or a long-press on a Places circle (`EditFavoriteSheet`, `FavoritesStore.update`). Renaming only changes how the favorite displays (`FavoritePlace.displayTitle`) — selecting it still searches Google Places by the real name, so a nickname like "Mom's House" doesn't break re-opening the place card.
- iCloud sync for Favorites and Recents: both stores now read/write through `NSUbiquitousKeyValueStore` instead of local-only `UserDefaults`, so a favorite or recent search added on one device shows up on the user's other signed-in devices (`KeyValueStore` protocol makes the backing store swappable, so tests use an in-memory fake instead of needing a real iCloud account). Requires enabling the iCloud → Key-value storage capability for this App ID in the Apple Developer portal — the `com.apple.developer.ubiquity-kvstore-identifier` entitlement alone isn't enough without that. Honest limitation: iCloud key-value storage is last-write-wins per key, not a per-item merge, so editing favorites from two offline devices at once will have the later sync overwrite the earlier one's changes to the whole list.
- Search-along-route: during active navigation, a search button in the nav overlay opens category chips (Gas, Food, Coffee, EV Charging, Parking) that query Google Places Nearby Search around a point roughly a third of the way along the remaining route, and tapping a result adds it as a real stop that recalculates the live route in place (`SearchAlongRouteViewModel`, `SearchAlongRouteSheet`). Honest simplification: this searches near one point ahead rather than a true corridor along the whole remaining polyline — building an actual route-corridor search is real additional work this doesn't attempt yet.
- Real multi-stop routing: "Add Stop" opens a search sheet (`AddStopSheet`) and inserts the chosen place as a real waypoint (`DirectionsViewModel.stops`, `RouteStop`), passed to Google Routes as `intermediates` so the whole trip is one live-traffic-aware route through every stop in order, not separate legs stitched together. Stops show as orange pins on the map and as removable rows in the directions card. Google's Routes API doesn't support alternates alongside waypoints, so a route with stops shows exactly one option rather than three. The MapKit fallback has no multi-waypoint API, so a route with stops honestly reports it needs the Google Routes API rather than silently dropping stops.
- Real spoken turn-by-turn voice guidance (`VoiceGuidanceService`, `AVSpeechSynthesizer`): speaks the current maneuver on nav start, a "coming up" cue ~500ft before the next turn, the turn itself as you reach it, and an arrival announcement. The mute button is now a real toggle instead of an inert icon.
- Automatic rerouting: two consecutive GPS fixes more than 45m from the route polyline trigger a recalculation via the same `GoogleRoutesService` call Directions uses, carrying over the trip's avoid-tolls/highways/ferries preferences, and swap the new route in live.
- Apple-Maps-style home card: the app now opens with the sheet resting at a partial height showing the search bar, a "Places" row of saved-place circles with straight-line distances, a grouped "Recents" card, and a "Your Places"/Favorites collection tile. Scrolling the card pulls the sheet to full height. Each section header's chevron opens the full list (`SavedListSheet`) with swipe-to-remove. Apple's Home/Work entries and the curated "Guides We Love" shelf are editorial/private data we have no source for, so this shows only places you've actually saved on the device.
- Swipeable route alternates in the directions card: at rest the card pages horizontally through one route at a time with page dots, and swiping re-highlights the matching line on the map; pulled to full height it lists every alternate at once with the selected one outlined in blue — matching Apple Maps' collapsed/expanded directions card.
- In-app directions: "Get Directions" no longer hands off to Apple Maps. `DirectionsViewModel` computes a route via `MKDirections` for a Drive/Walk/Transit mode picker, drawn as a `MapPolyline` on our own map with the camera fit to it; the same bottom sheet shows a distance/ETA summary. Real turn-by-turn voice guidance is a private system feature Apple doesn't expose to third-party apps, so this deliberately shows the calculated route and ETA only, and says so in the UI rather than implying more.
- XCUITest suite (`WaypointUITests`) covering the collapsed search bar, focus-reveals-sections behavior, category pills, live suggestion selection into the place detail card, the profile sheet, the map style menu, and the full in-app directions flow (mode switching, staying in-app). Runs against a real Google Places API key.
- Google Places–backed place detail sheet: photo carousel, star ratings, reviews (author, rating, relative time, text), open/closed status with expandable weekly hours, tap-to-call phone, tap-to-open website, and tap-to-directions address. `GooglePlacesService` resolves a MapKit search result to a Google place via Text Search (New), then fetches Details with an explicit field mask. The same bottom sheet morphs from search into the place card, matching Apple Maps rather than stacking a second sheet. Google's Places API does not expose structured menu data or in-app ordering (that's private to Google's own app), so this surfaces photos/reviews/hours/contact info honestly rather than faking a menu.
- Search sections (tip card, Places, categories, Nearby, Recents) now only appear once the search field is focused — the collapsed sheet shows just the search bar, matching Apple Maps instead of always showing suggestions.
- Full Apple-Maps-mirrored UI pass: custom-positioned glass map controls (3D toggle + compass bottom-left, map-style menu + location button bottom-right, via MapKit's scope-based standalone controls), a blue-tinted glass search field with a profile placeholder button, real on-device voice search (`SpeechRecognitionService` via `SFSpeechRecognizer`/`AVAudioEngine`), a WeatherKit-backed floating weather widget (hidden until the WeatherKit capability is enabled with a paid account), an honestly-labeled "Nearby" section (`NearbyPlacesService`, real `MKLocalPointsOfInterestRequest` data) and dismissible tip card in place of Apple's private Siri/transit suggestions, and a local Favorites/"Places" feature (`FavoritesStore`) with a quick-add row.
- Apple-Maps-style search: a persistent Liquid Glass bottom sheet (collapsed/medium/large detents, map stays interactive underneath) with a floating search field, category shortcut pills (Restaurants, Coffee, Gas, Groceries, Hotels), live autocomplete suggestions via `MKLocalSearchCompleter`, and a "Recents" list persisted locally via `RecentSearchesStore`. Selecting a result resolves it with `MKLocalSearch`, drops a marker on the map, and recenters the camera.
- App icon (indigo-to-teal gradient with a pin/waypoint glyph) and accent color, replacing the placeholder that disabled icon compilation.
- Initial project scaffold: folder structure, XcodeGen `project.yml`, `.gitignore`, README, CHANGELOG, LICENSE, and gitignored `Secrets.xcconfig` / committed `Secrets.xcconfig.example` for the Google Places API key.
- Base MapKit map view centered on the user's current location, using `CLLocationUpdate.liveUpdates()` via `LocationManager` and `MapViewModel`. Shows a graceful in-app prompt with a link to Settings when location permission is denied or restricted, instead of a blank map.

### Fixed
- The app never actually read `GOOGLE_PLACES_API_KEY`: Xcode's auto-generated Info.plist (`GENERATE_INFOPLIST_FILE`/`INFOPLIST_KEY_*`) only recognizes Apple's known keys and silently drops custom ones, so the key from `Secrets.xcconfig` never reached `Bundle.main`. Switched to a real `Waypoint/Info.plist` with `$(GOOGLE_PLACES_API_KEY)` substitution, which Xcode's build system resolves correctly for arbitrary keys. Google Places integration did not work before this fix regardless of a valid key being configured.
- The Drive/Walk/Transit mode picker didn't update its selection when tapped (tapping "Walk" silently kept recalculating the driving route). Replaced the native `Picker(.segmented)` with explicit glass buttons bound directly to the view model, which resolved it.

### Changed
- Route preferences moved from a "Now / Avoid" row inside the directions card into the "Options" chip under the card's title, where Apple keeps them; the chip names the active preference (e.g. "Avoid Tolls") instead of reading "Options" when one is on. Alternate route lines are now drawn in a muted blue rather than gray so every option reads as a route you can pick.
- Raised deployment target from iOS 17.0 to iOS 26.0 and adopted Liquid Glass: the location-permission card uses `.glassEffect`/`GlassEffectContainer` and `.buttonStyle(.glassProminent)` instead of `.regularMaterial`. System chrome (map controls, sheets, toolbars) now renders with Liquid Glass automatically since the app links against the iOS 26 SDK.
