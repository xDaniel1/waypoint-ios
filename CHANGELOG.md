# Changelog

Keeping track of what I've added/changed/fixed as I go. Loosely follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added
- Background location during active navigation: requests "Always" authorization contextually (only when a trip actually starts, not on launch — Apple rejects apps that ask upfront) and lets location updates keep flowing if the app is backgrounded mid-drive, so rerouting/ETA stay accurate. Turned back off when the trip ends.
- Local notifications for the next turn when the app is backgrounded during navigation, using the same phrasing as the in-app voice guidance. This is honestly *local*, not push — there's no backend server to send anything from, so true remote/silent push isn't something this app can build without one.

## [0.2.0] - 2026-08-02

### Fixed
- Search bar needed two taps before the keyboard would actually pop up — the glass background was eating the first tap for its press animation. Fixed with a `simultaneousGesture` so focus happens right away.
- Was hammering the Google API way more than needed. Place detail was re-fetching full details every time you opened the same place, even ones you'd already seen. Added a simple in-memory cache (1 hour TTL) so repeat opens are free. Also added a debounce on route recalculation so flipping avoid-tolls/highways toggles back to back doesn't fire a request per toggle.

### Fixed
- Favorites were unreachable: the only "Add to Favorites" control (a circle in the search-results list) only rendered when the results list was showing an empty query *and* a place was already selected — a state combination the app's own navigation never produced, since selecting a place always cleared the query-empty condition and left the results list. Added a real favorite-star toggle to the place detail card itself (`favoriteButton`, next to share/close), the reachable, expected location.

### Fixed
- All Google API calls (Places, Routes, Weather, Air Quality, Roads) started failing app-wide — place details, search, directions, weather, and Around Me all broke — after the Google API key was restricted to this app's iOS bundle ID in Cloud Console (the security fix flagged earlier in this project). That restriction is enforced by an explicit `X-Ios-Bundle-Identifier` request header, not inferred automatically, and nothing in the app was setting it. Added a shared `GoogleAPIRequest.addBundleIdentifierHeader()` used by every Google-calling service. Places *photos* needed a separate fix — `AsyncImage` has no way to attach custom headers — so added `GooglePhotoImage`, which fetches the image data manually with the header set, as a drop-in replacement everywhere a Google photo URL was rendered.
- Directions card's route-pager page dots read as jammed against the sheet's bottom edge with no breathing room, unlike Apple Maps' spacing — added bottom padding to match.

### Added
- Search-along-route — while navigating, a search button on the nav overlay lets you pull up Gas/Food/Coffee/EV Charging/Parking near where you're headed and add one as a stop without leaving the route. Right now it searches near a point about a third of the way down the remaining route rather than the whole path — good enough for now, might revisit later.
- Real multi-stop routing — "Add Stop" opens a search sheet and adds the place as an actual waypoint sent to Google Routes, so it's one real route through all your stops instead of separate legs glued together. Only shows one route option when you have stops since Google's Routes API doesn't do alternates + waypoints at the same time.
- Spoken turn-by-turn voice guidance using AVSpeechSynthesizer — announces the current turn, a heads-up before the next one, and arrival. Mute button actually works now.
- Auto-reroute — if you drift off the route it recalculates automatically instead of just sitting there wrong.
- Redid the home screen to look more like Apple Maps — partial-height sheet with search bar, saved places row, recents, favorites. Scrolling up expands it to full height.
- Swipeable route alternates in the directions card, matching how Apple Maps lets you page through route options.
- In-app directions — no more bouncing out to Apple Maps. Computes the route with MKDirections, draws it on our own map, shows distance/ETA. (Can't do real turn-by-turn since Apple doesn't expose that to third-party apps.)
- UI test suite covering search, category pills, place detail, and the directions flow.
- Google Places-backed place detail sheet — photos, ratings, reviews, hours, phone/website/address.
- Search sections only show up once you actually tap into the search bar, matching Apple Maps instead of dumping suggestions on you immediately.
- Full pass to make the UI look more like Apple Maps — custom map controls, glass search bar, real voice search, weather widget, Nearby section, tip card, Favorites with quick-add.
- Search with autocomplete, category pills, recents — Apple-Maps style bottom sheet.
- App icon + accent color.
- Initial project setup — folder structure, XcodeGen config, README/CHANGELOG/LICENSE.
- Base map view centered on current location, with a proper permission-denied screen instead of just showing a blank map.
- Crash/hang diagnostics (`CrashReportingService`), no third-party SDK or server: on iOS 27+, subscribes to MetricKit's `MetricManager.diagnosticReports` for real crash/hang/CPU/disk-write/memory-exception reports, persisted locally (last 20) and shown in a real "Diagnostics" section of the Profile sheet — replacing the profile screen's dead-end "Accounts aren't built yet" with something actually useful, and fixing its now-stale claim that favorites/recents are device-only (they sync via iCloud now). Below iOS 27, falls back to a same-launch "did last run end cleanly" signal (`lastRunEndedCleanly`, plain `UserDefaults`, works down to this project's iOS 26 floor) — cruder, but available immediately instead of MetricKit's typical multi-hour delivery delay. Honest limitation either way: this is on-device only, checked the next time someone opens the app — not a real-time alert.
- Congestion drawn directly on the map: driving routes now request Google's `speedReadingIntervals` (per-segment live-traffic speed) and draw the slow/jammed stretches as orange/red overlays on top of the base route line, in both the directions preview and during active navigation (`CongestionSegment`) — not just the existing whole-route "has traffic" badge. Honest gap: Google's Routes API only exposes per-segment *speed*, not discrete incident type/location (accident, closure, construction), so this draws congestion, not incident icons — that would need a different data source.
- Live Activity / Dynamic Island + home screen widget: a new `WaypointWidgetsExtension` target adds a Lock Screen/Dynamic Island Live Activity (`NavigationLiveActivityWidget`, via `LiveActivityService`) showing destination, ETA, current instruction, and remaining distance while navigating — started on GO, refreshed every ~20s or immediately after a reroute, ended with the trip. A home screen widget (`NextDestinationWidget`) shows the same destination/ETA for the active trip, or an honest "No active trip" state otherwise (no on-device trip prediction — that's a private Apple/Siri capability). The widget extension can't read the app's in-memory state directly, so `NavigationWidgetDataStore` writes a small snapshot to a shared App Group container and force-reloads the widget's timeline on every change. Live Activity updates are local (the app pushes them directly while running); they will NOT keep updating if the app is force-quit or fully backgrounded for a long time — that needs remote/push-updated Live Activities (APNs + a server component), out of scope here.
- "Around Me" quick-category grid on the home card: Gas, Food, and EV Charging chips that run a real Google Places Nearby Search around the user's current location (`AroundMeViewModel`), expanding into a result strip with photo, rating, and distance — tapping a result opens the same real place-detail card as any other search result. Tapping the open category again collapses the strip.
- Editable Favorites: rename a saved place and give it a custom emoji/color pin instead of the auto-derived category icon, via an edit sheet opened from a swipe action in the full Favorites list or a long-press on a Places circle (`EditFavoriteSheet`, `FavoritesStore.update`). Renaming only changes how the favorite displays (`FavoritePlace.displayTitle`) — selecting it still searches Google Places by the real name, so a nickname like "Mom's House" doesn't break re-opening the place card.
- iCloud sync for Favorites and Recents: both stores now read/write through `NSUbiquitousKeyValueStore` instead of local-only `UserDefaults`, so a favorite or recent search added on one device shows up on the user's other signed-in devices (`KeyValueStore` protocol makes the backing store swappable, so tests use an in-memory fake instead of needing a real iCloud account). Requires enabling the iCloud → Key-value storage capability for this App ID in the Apple Developer portal — the `com.apple.developer.ubiquity-kvstore-identifier` entitlement alone isn't enough without that. Honest limitation: iCloud key-value storage is last-write-wins per key, not a per-item merge, so editing favorites from two offline devices at once will have the later sync overwrite the earlier one's changes to the whole list.
- Search-along-route: during active navigation, a search button in the nav overlay opens category chips (Gas, Food, Coffee, EV Charging, Parking) that query Google Places Nearby Search around a point roughly a third of the way along the remaining route, and tapping a result adds it as a real stop that recalculates the live route in place (`SearchAlongRouteViewModel`, `SearchAlongRouteSheet`). Honest simplification: this searches near one point ahead rather than a true corridor along the whole remaining polyline — building an actual route-corridor search is real additional work this doesn't attempt yet.
- Real multi-stop routing: "Add Stop" opens a search sheet (`AddStopSheet`) and inserts the chosen place as a real waypoint (`DirectionsViewModel.stops`, `RouteStop`), passed to Google Routes as `intermediates` so the whole trip is one live-traffic-aware route through every stop in order, not separate legs stitched together. Stops show as orange pins on the map and as removable rows in the directions card. Google's Routes API doesn't support alternates alongside waypoints, so a route with stops shows exactly one option rather than three. The MapKit fallback has no multi-waypoint API, so a route with stops honestly reports it needs the Google Routes API rather than silently dropping stops.
- Real spoken turn-by-turn voice guidance (`VoiceGuidanceService`, `AVSpeechSynthesizer`): speaks the current maneuver on nav start, a "coming up" cue ~500ft before the next turn, the turn itself as you reach it, and an arrival announcement. The mute button is now a real toggle instead of an inert icon.
- Automatic rerouting: two consecutive GPS fixes more than 45m from the route polyline trigger a recalculation via the same `GoogleRoutesService` call Directions uses, carrying over the trip's avoid-tolls/highways/ferries preferences, and swap the new route in live.
- Apple-Maps-style home card: the app now opens with the sheet resting at a partial height showing the search bar, a "Places" row of saved-place circles with straight-line distances, a grouped "Recents" card, and a "Your Places"/Favorites collection tile. Scrolling the card pulls the sheet to full height. Each section header's chevron opens the full list (`SavedListSheet`) with swipe-to-remove. Apple's Home/Work entries and the curated "Guides We Love" shelf are editorial/private data we have no source for, so this shows only places you've actually saved on the device.
- Swipeable route alternates in the directions card: at rest the card pages horizontally through one route at a time with page dots, and swiping re-highlights the matching line on the map; pulled to full height it lists every alternate at once with the selected one outlined in blue — matching Apple Maps' collapsed/expanded directions card.
- In-app directions: "Get Directions" no longer hands off to Apple Maps. `DirectionsViewModel` computes a route via `MKDirections` for a Drive/Walk/Transit mode picker, drawn as a `MapPolyline` on our own map with the camera fit to it; the same bottom sheet shows a distance/ETA summary. Real turn-by-turn voice guidance is a private system feature Apple doesn't expose to third-party apps, so this deliberately shows the calculated route and ETA only, and says so in the UI rather than implying more.
- XCUITest suite (`WaypointUITests`) covering the collapsed search bar, focus-reveals-sections behavior, category pills, live suggestion selection into the place detail card, the profile sheet, the map style menu, and the full in-app directions flow (mode switching, staying in-app). Runs against a real Google Places API key.
- Google Places–backed place detail sheet: photo carousel, star ratings, reviews (author, rating, relative time, text), open/closed status with expandable weekly hours, tap-to-call phone, tap-to-open website, and tap-to-directions address. `GooglePlacesService` resolves a MapKit search result to a Google place via Text Search (New), then fetches Details with an explicit field mask. The same bottom sheet morphs from search into the place card, matching Apple Maps rather than stacking a second sheet. Google's Places API does not expose structured menu data or in-app ordering (that's private to Google's own app), so this surfaces photos/reviews/hours/contact info honestly rather than faking a menu.
- Search sections (tip card, Places, categories, Nearby, Recents) now only appear once the search field is focused — the collapsed sheet shows just the search bar, matching Apple Maps instead of always showing suggestions.
- Full Apple-Maps-mirrored UI pass: custom-positioned glass map controls (3D toggle + compass bottom-left, map-style menu + location button bottom-right, via MapKit's scope-based standalone controls), a blue-tinted glass search field with a profile placeholder button, real on-device voice search (`SpeechRecognitionService` via `SFSpeechRecognizer`/`AVAudioEngine`), a WeatherKit-backed floating weather widget (hidden until the WeatherKit capability is enabled with a paid account), an honestly-labeled "Nearby" section (`NearbyPlacesService`, real `MKLocalPointsOfInterestRequest` data) and dismissible tip card in place of Apple's private Siri/transit suggestions, and a local Favorites/"Places" feature (`FavoritesStore`) with a quick-add row.
- Apple-Maps-style search: a persistent Liquid Glass bottom sheet (collapsed/medium/large detents, map stays interactive underneath) with a floating search field, category shortcut pills (Restaurants, Coffee, Gas, Groceries, Hotels), live autocomplete suggestions via `MKLocalSearchCompleter`, and a "Recents" list persisted locally via `RecentSearchesStore`. Selecting a result resolves it with `MKLocalSearch`, drops a marker on the map, and recenters the camera.
- App icon (indigo-to-teal gradient with a pin/waypoint glyph) and accent color, replacing the placeholder that disabled icon compilation.
- Initial project scaffold: folder structure, XcodeGen `project.yml`, `.gitignore`, README, CHANGELOG, LICENSE, and gitignored `Secrets.xcconfig` / committed `Secrets.xcconfig.example` for the Google Places API key.
- Base MapKit map view centered on the user's current location, using `CLLocationUpdate.liveUpdates()` via `LocationManager` and `MapViewModel`. Shows a graceful in-app prompt with a link to Settings when location permission is denied or restricted, instead of a blank map.

### Fixed
- API key wasn't actually being read at runtime — Xcode's auto-generated Info.plist doesn't support custom keys, so `GOOGLE_PLACES_API_KEY` never made it into the app no matter what was in Secrets.xcconfig. Switched to a real Info.plist to fix it.
- Drive/Walk/Transit picker didn't actually switch modes when tapped. Swapped the native segmented picker for custom buttons wired directly to the view model.

### Changed
- Moved route preferences (avoid tolls/highways/etc) into the "Options" chip instead of a separate row, matching where Apple puts it.
- Bumped deployment target to iOS 26 to use Liquid Glass instead of the old material backgrounds.
